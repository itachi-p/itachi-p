# 原子タグ体系の確定と、登録時フィルタへの切り替え

対象: itachi-p/my-acronym-app
日付: 2026-08-26
前段: `2026-08-24_category-taxonomy-db-sync.md` / `2026-08-24_atomic-tag-decomposition.md`

前日までにタグ方式への移行方針と原子タグ化の必要性を決めた。本日はそれを実データに適用し、
発生源側の対処まで進めて公開可能な状態にした。

## 判断

### 1. 登録基準を「雑学クイズ性テスト」として定義 — 採用

中心テスト: **その略語を知らないと、実務・報道・専門文書で文意が取れないか。**
知っていても雑学が増えるだけのものは対象外とする。

補助ルール:
- A1: 略語が2文字以下は原則拒否。許可リスト方式（BS / PL / LP / EV / pH）
- A2: 学位は MBA のみ
- A3: 企業名は原則拒否。明示的に許可したものだけ例外
- A4: 大学名は「文脈で説明なしに出る」ものに限る
- A5: IT は開発・運用の内輪だけで通じる用語を拒否。他分野に応用できる原則（YAGNI, DRY）は採用

根拠: A1 は実データで裏が取れた。2文字略語6種（BS/EV/JD/LP/PL/pH）だけで19件あり、
DB全体の15%を占めていた。「意図しないものが一度に大量に入る」という懸念がそのまま数字に出ている。

### 2. A6（廃止機関・歴史用語は拒否）を撤回 — 訂正

当初、廃止済みの機関を拒否対象としたが撤回した。
根拠: PWA（Public Works Administration）や SIOP は、
米国史やペイパルマフィア周辺の文脈で調べる需要が実在する。
「現在使われているか」ではなく「調べる動機があるか」で判定すべきだった。

### 3. D4（雑学クイズ性）に語源の例外を追加 — 採用

根拠: セキュリティ用語の PPAP（パスワード付きZip送付）は、
2016年の楽曲 PPAP をもじって命名された。語源にあたるレコードを消すと、
残ったレコードの由来が辿れなくなる。
規則として「他の採用エントリの語源・背景になっているものは採用」とした。
DIY も同様に許容した（ユーモアを残す判断）。

### 4. 低価値レコードの削除 — 実行（130 → 99件）

削除の内訳: 明示指定5 / 雑学クイズ性2 / 名称不確実2 / 実在性が疑わしい4 /
表記ゆれ重複3 / 自己言及1 / 学位4 / 名称の誤り2 / 業界内部特化6 / 学術ニッチ4 /
分野の不一致2（SLA第二言語習得、TOC全有機炭素）/ WID 2件。

WID の2件（Windows Internal Database / Women in Development）は、
World Inequality Database を登録しようとした際に Groq が同時登録した「期待と違う2件」であり、
本件で対処しようとしている問題の実例そのものだった。

### 5. 19原子タグ / 7表示グループを確定 — 採用

```
ビジネス : 経営 / 組織・人事
金融     : 金融 / 株式・投資 / 会計 / 経済
政治     : 政治 / 行政 / 国際機関
軍事     : 軍事 / 安全保障
テック   : IT / AI / ソフトウェア開発 / 通信・放送
学術     : 学術 / 医療 / 教育
その他   : その他
```

適用の結果、「その他」は 18件 → 3件（全体の3%）に減少した。
昇格閾値 N・統合閾値 M の議論は不要な水準になったため保留のままとする。

### 6. 表示グループ「IT」を「テック」に変更 — 訂正

根拠: 原子タグに「ロボティクス」や「AI」を含む前提で設計しながら、
表示グループ名を「IT」のまま残していた。
ロボティクスはテクノロジーだが IT ではない。VLA の分類検討で判明した階層
（テクノロジー ⊃ IT / ロボティクス）を、表示層の名前に反映していなかった。

**コード変更は不要だった。** ボタンは display_group から動的生成されているため、
DB を1行 UPDATE するだけで反映された。分類層と表示層を分離した設計の効果が実証された形。

### 7. acronyms_category_check を削除し、category 列を legacy 化 — 採用

根拠: 原子タグ名（経営、AI 等）は旧6値の CHECK 制約を通らない。
読み取りはタグ経由に切り替わっているため、CHECK を維持する意味がない。
制約を外し、category には主タグの display_group を書く二重書きとした。
列自体の削除は次フェーズに残す。

### 8. ゴミデータ対策を定期掃除から登録時フィルタへ移行 — 採用

根拠: 定期的に掃除を走らせるより、入口で弾く方が総コストが低い。
また掃除用 Skill 自体の動作検証にもコストがかかるため、
発生源を絞る方が先に効く。

実装:
- 機械判定 D1（名称不確実）/ D2（自己言及）/ D3（正規化重複）/ D5（訳が無意味）
- Groq プロンプトへの採用基準の埋め込み（中心テスト＋A1〜A5）
- 1回の検索あたりの INSERT 上限
- 拒否は削除ではなく `rejected_candidates` に理由コード付きで記録

**D3 の正規化ユニークインデックスが中核。**
`lower(regexp_replace(full_spelling,'[^a-zA-Z0-9]','','g'))` で比較することで、
`Non-Profit Organization` と `Nonprofit Organization` を同一と判定しつつ、
`Balance Sheet` と `Base Station` は別物として通す。
既存の複合ユニークキーの設計思想（同一略語の別概念は共存させる）を変えずに、
表記ゆれだけを弾ける。

### 9. 拒否したものを削除せずログに残す — 採用

根拠: 弾いた理由が残っていれば、誤爆（正当な略語を拒否した）を後から検証できる。
削除してしまうと、フィルタが厳しすぎるかどうかを判定する材料が失われる。

### 10. タグ名「安全保障」を据え置き — 採用（「紛争・安全保障」案を破棄）

Hamas / IRA / PKK / PLO に「安全保障」タグが付くことへの違和感が提起された。
「安全保障」は守る側（NATO, NORAD）と脅威の側（武装組織）の両方を含む領域名であり、
分類としては正しいが、ラベルとしては誤読を招く。

「紛争・安全保障」への改名を検討したが破棄。
根拠: 表示グループのボタン幅に制約があり、タグ名を長くすると
「ビジネス・経営」のような複合名に逆戻りする。図書館分類と同じ前提で運用する。

「テロ組織」というタグを作らなかったのは、これが認定主体によって変わる政治的ラベルであるため。
PLO は現在パレスチナ自治政府の母体であり、IRA も和平合意後に政治プロセスへ移行している。
辞書として中立を保つには、行為の性質か領域で分類する方が安全。

### 11. ヘルプを単一マークダウンで管理 — 採用（GitHub Pages 案を破棄）

根拠: GitHub Pages は公開先・ビルド設定・画像配置を新たに管理することになる。
アプリ内に `/help` を置けば、既存の Vercel ホスティングとレスポンシブ対応をそのまま使える。
`content/help.md` を唯一の情報源とし、文言修正にコード変更を伴わせない。

生HTML は無効のままとした。このファイルは信頼できる管理下にあるが、
description 列に HTML を許可しなかった判断と揃え、経路自体を作らない。

### 12. Next.js 16 へのメジャーアップグレード — 保留

npm audit が6件の high を報告しているが、いずれも開発時依存（postcss, eslint-config-next 等）に起因する。
`npm audit fix --force` は Next.js 16 へのメジャーアップグレードを伴うため、
ヘルプページ追加という目的に対してリスクが釣り合わない。TODO に残す。

## 失敗と訂正

### 副タグ付与SQLで、同一略語の別レコードに誤爆した

主タグの精緻化では `(acronym, full_spelling)` の両方で対象を指定していたのに、
副タグの付与では `acronym` だけで一致させていた。結果:

- `SIOP | Sales, Inventory and Operations Planning`（SCM用語）に「政治」が付いた
- `PPAP | Pen-Pineapple-Apple-Pen`（楽曲）に「経営」が付いた
- `ROI | Region of Interest`（画像処理）に「経営」「株式・投資」が付いた

このDBは「同じ略語で意味が違うレコードが複数ある」ことを前提に設計されている。
その前提を、自分が書いたSQLの側で無視した。

### 主タグ変更時に PK 重複でエラーになった

`FDA` の主タグを「行政」に変更しようとしたが、既に副タグとして「行政」が付いており、
`acronym_tags_pkey` に違反した。
変更先と衝突する副タグを先に削除する順序に修正した。

### Neon コンソールの画面外の文字を推測で補った

テーブルエディタに表示された `ULT` を `DEFAULT` の末尾と判断したが、
これは確認ではなく推測だった。結果的に正しかったが、根拠がない。
スクリーンショットに写っていない文字は読めない、という制約を明示していなかった。
