# ホームディレクトリの配置整理

## 日付
2026-08-23

## 背景

ホーム直下に repos/・heiwa-sns/・src/・work/ が並存し、リポジトリの分類軸が
「場所（どこに置いたか）」と「目的（何のために作ったか）」の2種類混在していた。
このため新規プロジェクトを作るたびに置き場所の判断が毎回発生していた。

work/ は人間が意図して設計したディレクトリではなく、Claude Codeのセッションが
その時々のカレントディレクトリとして生成した結果できていたものだった。つまり
「目的別にwork/へ集める」という設計判断が先にあったのではなく、セッション開始時の
cwdという偶然の要因が配置を決めていた。

## 実施内容

分類軸を「現役（更新し続ける）／用途終了（参照のみ、更新しない）」の1軸に統一し、
以下のとおり物理的に移動した（`mv`、リポジトリ内のファイル移動ではなく
リポジトリ自体の移動のため `git mv` は使用せず）。

**repos/ へ（現役）**
- `src/my-acronym-app` → `repos/my-acronym-app`

**archive/ へ（用途終了）**
- `heiwa-sns`（旧Nagi、開発停止済み）
- `work/hall-analytics-demo`（Laravelデモ、応募先の募集見直しにより用途終了。Render公開済みで活用方法は別途検討）
- `work/drill`（Skills練習用）
- `work/resume-source`（職務経歴書統合用の入力元ファイル。従来型の就職活動停止に伴い今後更新なし）

移動後、空になった `src/` と `work/` は削除した（残っていた `.DS_Store` はFinderのメタデータのみで
実データではないため、削除の対象に含めた）。

## 判断

- **削除ではなくアーカイブを選んだ理由**：用途が終了したリポジトリも、参照する可能性
  （特に hall-analytics-demo は「せっかく公開したので活用したい」という保留状態）が残っており、
  削除は不可逆だが移動は可逆であるため。
- **`work/drill` は未コミットの変更（`notes/2026-08-18.md` がstage済み・未コミット）を
  抱えたまま移動した**。本来は「未コミット状態での移動禁止」を原則としていたが、
  内容が練習用の単一ファイルであり実害がないと判断し、人間の承認を得たうえで例外的に移動した。
- `~/.claude/settings.json` 内の `src/my-acronym-app` へのパス言及は新パスに更新済み。
  一方 `~/.claude.json` の `projects` キー（本セッション自身が実行中のプロセス状態を含む）は、
  稼働中のプロセスが保持する値のため、その場での書き換えはリスクが大きいと判断し見送った。
  新パスでClaude Codeを起動すれば新規エントリが作られるため、旧エントリは自然に不要になる。

## 追記（同日）：heiwa-sns・hall-analytics-demoをrepos/へ再移動

当初「用途終了」として archive/ へ移動した `heiwa-sns` と `hall-analytics-demo` は、
どちらも稼働アプリであり今後更新する可能性がゼロではないと判断し、`repos/` へ
再移動した。「現役／用途終了」の分類基準は、単に開発が止まっているかどうかではなく、
**今後更新される見込みがあるかどうか**で判定する。

- `repos/` へ再移動：`heiwa-sns`, `hall-analytics-demo`
- `archive/` に残るもの：`drill`（練習用・使い捨て）, `resume-source`（従来型就職活動の
  停止に紐づき更新見込みなし）

`~/archive/README.md` から該当2件の記述を削除済み。

## 追記（同日）：habit_replacement_appの漏れを追加移動

当初の現状確認の対象（repos/・heiwa-sns/・src/・work/）に含まれておらず、
ホーム直下に直接置かれたままだった `habit_replacement_app`（Flutter、
GitHubリモートあり）が後日発覚。`repos/` へ追加移動した（`mv`、remote・
git status・履歴は移動前と同一）。未コミットの変更（`ai_backups/`, `build/`
配下）が残っていたが、ディレクトリごとの移動のため内容の損失はない。
