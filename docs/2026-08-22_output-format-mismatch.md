# 出力形式ごとに検査軸を切り替える

対象：note記事「シン・世界秩序とはなんぞや？―勝っても報われない土俵から降りられるか」の推敲〜公開

---

## 主張と出力形式の不一致は、本文の読み返しでは検出できない

- **症状**：本文が仕上がった後に、タイトル・ヘッダー画像・タグ・指示語で立て続けに不一致が見つかった。いずれも本文だけを何度読み返しても出てこなかった。
- **制約**：本文を読むとき、書き手は自分の主張を既に知っている状態で読む。だから「本文と主張が合っているか」は検査にならない。不一致は、主張を**別の形式に変換した瞬間**にだけ生まれる。タイトルは30字への圧縮、画像は空間配置への変換、タグは検索語への変換。変換のたびに元の主張から情報が落ち、落ち方は形式ごとに違う。
- **規則**：完成後、形式ごとに別の軸で1回ずつ検査する。本文の通し読みで代替しない。
  - タイトル：記事が**実際に答えている問い**と一致しているか
  - 図・画像：本文の最も繊細な区別を担わせていないか／構図が主張と矛盾していないか
  - タグ：意味の正しさでなく、読者の**期待値の一致**で選べているか
  - 太字：太字だけを繋いで読んで骨子が通るか（強調ではなく拾い読みの経路）
  - 注・免責：同じ体裁の注が重複していないか／対象の直近に置かれているか
- **適用範囲**：複数の出力形式を持つ成果物（記事、スライド、アプリのUI＋README）に有効。単一形式のもの（コードのみ、メモのみ）には効かない。また、主張が明確に固まっていない段階では使えない（比較対象がないため）。

## タイトルは書き終えてから作る

- **症状**：仮タイトル「シン・世界秩序とはなんぞや？」は「世界秩序とは何か」を約束していたが、記事が答えていたのは「勝っても報われない構造から降りられるか」だった。
- **制約**：仮タイトルは書き始めの時点の見込みで付ける。書く過程で主題は移動する。移動した分だけ必ずズレる。ズレは書き手には見えない（自分は結論を知っているので、仮タイトルを結論で補完して読んでしまう）。
- **規則**：公開直前の最後の工程としてタイトルを作り直す。「この記事が答えている問いを1つ挙げよ」に答え、その答えからタイトルを組む。答えを出せない場合は記事側の問題。
  - 併せて：タイトル内に予防線（「まだ序盤」「素人ですが」）を置かない。本文冒頭で同じことを書いているなら二重。
  - 解決策を持たない記事のタイトルに、解決を約束する語（「〜する方法」「〜への道」）を使わない。
- **適用範囲**：記事・レポート・提案書など、タイトルが読むかどうかの判断に使われるもの全般。逆に、識別子として機能すればよいもの（ログのファイル名、コミットメッセージ）には適用しない。

## 図に、方向を持たない形しか担わせない

- **症状**：「競争 vs 協力」を左右2分割で描いた画像が、記事の主張（相対評価による優劣判定からの脱出）と衝突した。左に俗物、右に善人という人格の優劣判定になっていた。
- **制約**：原因は表情や色ではなく**2分割構図そのもの**。左右分割は、構造的に「良い側／悪い側」を出力する。図は本文より先に読まれ、本文より強く記憶されるので、図が出した優劣判定は本文の説明で打ち消せない。
- **規則**：図に任せるのは、**方向を持たない形**だけ（構造・循環・因果）。比較を描く必要がある場合は、**両側に同じ登場人物を置く**。そうすると比較対象が人格から構造へ移る。
  - 検査手順：図だけを見た第三者が、本文を読まずにどんな価値判断を受け取るかを1文で言えるか。それが本文の主張とズレていたら図を捨てる。
- **適用範囲**：主張に「AとBの優劣ではなく構造の差である」といった繊細な区別が含まれる場合に必須。単純な手順図・構成図には不要。

## 主張と例示の論理型を揃える

- **症状**：「持っている量と与える姿勢に相関はない」と書いた直後に「貧しい者の方が与える傾向がある」と書き、無相関の主張と負の相関の主張が同居した。指示語の修正では直らなかった。
- **制約**：「傾向がある」と「相関がない」は論理型が違う。型が違う文を同じ段落に置くと、指示語や接続をどう調整しても矛盾は残る。
- **規則**：主張が「相関がない」型のとき、例示は**存在の主張**（「〜もいる」「〜こともある」）に限定する。「〜の方が多い」「〜の傾向がある」は使わない。逆方向の例を併記して「その逆もある」で閉じる。
- **適用範囲**：統計的な主張と具体例を併置する場面全般。単一方向の主張（「Aが増えるとBが増える」）を書いている場合は、傾向の例示で正しい。

## 記録は成果物の副産物として出す

- **症状**：3〜4ヶ月、GitHubへの思考ログが途絶えた。当初の動機（採用時に見られることを想定）が外的だったことを自己分析していたが、それだけでは説明が足りない。
- **制約**：動機の種類以前に、記録が**成果物とは別立ての作業**だったこと。記録は常に「本来やりたかったことが終わった後」に来る。終わった解放感と競合する位置にあるものは、動機が内的でも落ちる。
- **規則**：記録は、成果物が仕上がった直後の同じ流れの中で、独立した意思決定を挟まずに出す。出力時点でファイル名・本文・コミットメッセージが揃っていること（判断が残っていると、そこで止まる）。
- **適用範囲**：記録・振り返り・ドキュメント全般。逆に、成果物より先に置ける記録（作業前の仮説設定）はこの制約を受けないので、別扱いでよい。

## 補足：外的信号の置き換えに注意

活動の主軸をGitHubのログからnote記事に移す場合、依存する外的信号が「採用担当の目」から「スキの数」に変わるだけで、構造は同じになり得る。抜け道は外的動機を断つことではなく、**外的信号なしでループが閉じる完了条件を持つこと**。

今回の完了条件：記事が仕上がった＋再利用できるパターンが抽出できた。公開1時間半でスキ0件だが、この条件は満たしている。
